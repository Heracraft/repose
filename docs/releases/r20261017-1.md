### A gap in this release's own verification, and six tests that race

The `go test ./...` runs before the push were made OUTSIDE the dev shell,
so every Postgres-backed test under `internal/api/` SKIPPED with
`testdb: no DATABASE_URL and no initdb on PATH`. RELEASE.md asks for "a
real Postgres for the api packages" and did not get one. CI has a
database, ran them, and the Go job on the released commit came back red
with `TestHelloRefusedClosesTheStream`. The suite was re-run afterwards
in the dev shell, which has initdb, and that is the run the numbers below
come from.

Six tests fail only in a full parallel run and pass alone. None is a
defect in the code under test; each races its own setup:

- `internal/api/hostmgr` TestHelloRefusedClosesTheStream — CI's failure.
  15 consecutive runs with a database at GOMAXPROCS=2: pass. Passed in
  the full database suite too.
- `internal/api/http` TestStartUnreachableText — writes
  `hosts.state='unreachable'` into the database and expects the api's own
  view to have caught up by the next request. 6 runs alone and the whole
  package alone (29.7 s): pass.
- `internal/cli` TestLaptopPortTakenOnAnyAddress — a port-release race
  ("port reads as taken after ::1 let it go").
- `internal/gateway` TestFailuresStillBanAndTheBanIsLogged.
- `internal/guestd/freeze` TestWatchdogThawsAndWarns.
- `internal/hostd/guest` TestBootDialFindsGuestdSoon — fixed in this
  release (ForkPointTTL was 50 ms, shorter than the test's own next
  lines).

tmux-socket-path fixed three that were failing for the fixture's own
reasons: the tmux socket path built from the test's name, the fork timing
floor, and that TTL. The six above want the same treatment — wait for
the condition rather than assume it — and until they get it, a release
gate's red is ambiguous, which is the real cost.

Two lessons for the next conductor, both learned here the hard way: run
the suite inside `nix develop ./nix`, or the api tests lie by skipping;
and a `go test` wrapper exits 0 while the package fails, so read the log
body and never the exit code.

## The edge was not switched, and should not be

The batch's target set includes `edge`, and that is a false positive
cpu-weight's own note called out. Verified rather than trusted, on the
released main: `go list -deps ./cmd/gateway` gives 6 internal packages,
42 non-test Go files changed between 293a8dba and 006301c7, and **none**
of them lies in any of those 6. The only changed file inside a gateway
dependency is `internal/obs/metrics/families_host_test.go`, which Go does
not compile into a binary.

`needs` is computed from changed packages, and a `_test.go` in a
dependency is enough to flag a target whose binary cannot have changed.
That is worth fixing in the needs computation; until then a conductor
should check the import graph before switching the edge, because the
first switch onto it drops every open SSH session once.

host-01 was switched (see cpu-weight above). The edge was left alone.
