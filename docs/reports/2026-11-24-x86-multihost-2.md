N1's cause, reproduced. The Latitude image ships with nothing in `/var/lib/apt/lists` (0 files) and with no `/usr/share/doc/linux*`. The installer's check runs before the installer's own `apt-get update`. At that point, `apt-get changelog linux-modules-6.8.0-149-generic` fails with `E: Failed to fetch changelog:/linux.changelog Changelog unavailable for linux=6.8.0-149.149`.

- After the install had filled the apt lists, I ran the same `kernel_fix_shown` function, piped to `sudo bash -s`. It printed SHOWN. Line 27 of the changelog reads `- ipv4: validate checksum_start before completing checksum`.
- Box B, still untouched, printed NOTSHOWN.
- A reinstall on B, which still had its apt lists, printed no warning.

So a careful customer is told that a fixed box is exposed. The remedy the warning gives probably clears it, because it runs `apt-get update`. But it also asks for a full upgrade and a reboot, and this image carries `linux-image-7.0.0-43-generic` (HWE). After the reboot, the box may run a kernel nobody has tested here. Not run: the full-upgrade and reboot path.

## Method and what could not run

- **Where commands ran.** The CLI ran as the customer types it, from woker-1 (`~/lab2/bin/r`, with its own `XDG_CONFIG_HOME`) and on each box. Sessions were minted with `~/briefs/mint-owner-cli-session.sh` and with a local copy of the same logic.
- **The join argument.** It was written to a 0600 copy and read into a shell variable for the journal check. It was never printed, and the copy was removed. The dashboard's Add a host text was redacted before it was printed.
- **Timing and states.** Times are from `date +%s%N` around each command. States were polled every 3 to 5 s, with change-only logging.
- **Offline.** I made a box offline with `iptables -I OUTPUT -p udp --dport 51820 -j DROP`, with a `systemd-run` timer to undo it.
- **Dashboard.** Playwright 1.63 with nixpkgs Chromium 157, through `ops/dev/dashboard-session`. Screenshots are 1x viewport captures in `~/lab2/pw/`.
- **What was made and removed.**
  - Machines: e2e-x86-p1 to p4, o2, c1 to c5, c7 to c12, f1, f3 to f8, s1 to s4, s3fork and w1, all destroyed. e2e-x86-o1, c6, c13, f2, f9, g1, w2 and dash1 were refused and never existed.
  - Hosts: e2e-x86-a, e2e-x86-b (twice) and e2e-x86-c were each added and removed. At the end, `repose host ls` answered `You have no hardware of your own.`.
  - No non-e2e project touched a test host. At the end, 22 projects were on the account, none of them e2e and none on an e2e host.
- **Not run.**
  - N1's full-upgrade and reboot path.
  - Power loss, which pass 1 measured.
  - Agents past a shell.
  - Plan gates and the paying-account wording, because the account is billing-exempt.
  - Debian, Intel and nested virtualisation.
  - Unattended updates over days.
- **Rules that bit me.** The first reboot watcher's loop ended early, on a stale `running` reading. I re-ran it with a 200 s change-only watch and kept that run's figures. The pass 1 known_hosts entry for A's reused IP stopped the mint script until I replaced it.
