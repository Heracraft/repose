For the current status of M-1, M-2, M-4 and M-5, see [review-2026-09-21.md](review-2026-09-21.md).

What was reviewed: everything merged into `main` at `43efc53` plus this
branch: `nix/hosts`, `nix/guest`, `nix/edge`, `nix/overlay`, `cmd/hostd`

verifiable yet" rather than passed.

Method: each boundary row of `docs/workstreams/14-security.md` §5 was
traced from `docs/SECURITY.md` to the file that implements it, and the
implementation was compared with the interface doc that binds it. Two
claims were reproduced on the dev box (virtiofsd's sandbox modes; the
nftables ruleset by reading the VM test). Line numbers are for this
branch; "before" numbers are for `43efc53`.

Severity: **High** breaks a tenant boundary or the host, or blocks every
guest; **Medium** weakens a boundary, a promise in the docs, or an audit
path; **Low** is defence in depth, hygiene or a doc mismatch.

## Secrets handling review (14 §5)

- **04 guestd** (reviewed, no findings beyond L-5): values land as 0400
  `dev` files on tmpfs; `secrets.env` is 0400 and shell-quoted; reserved
  sshd material goes to `/run/repose` root-owned; validation precedes the
  first write; nothing logs a value; the whole-set semantics make `rm`
  reach a running guest (I-30).
- **03 hostd**: secrets and sshd material stay in memory (`m.secrets`),
  never in bbolt, `guest.json` or `ch.args`; delivered after `Ready` over
  vsock. The gap noted here at review time, H-2 (a root hypervisor), is
  fixed by I-51; what remains is L-11.
- **hostdev**: M-4.
- **05 api** (reviewed 2026-09-20 by the M3 integration session): values
  are AES-256-GCM under a per-user DEK with the name as AAD
  (`internal/api/secrets/secrets.go` `Seal`/`Open`), the DEK wrapped by
  Key Vault and stored on every row; the Key Vault policy is Get, WrapKey,
  UnwrapKey (I-91; Get returns the public half only). Plaintext exists in
  `DecryptForGuest`'s callers alone: the CreateGuest/StartGuest/Restore
  and UpdateSecrets builders (`internal/api/ops/phases.go:156,213`), the
  platform's CA rows, and the build-log redaction set
  (`phases.go:383`, `buildlog.SetRedactions`), which keeps every secret
  value of the project in api memory for the length of the build (up to
  30 minutes) rather than a request; `ClearRedactions` runs when the op
  ends (`engine.go:516,543`). That is the price of the redaction the
  feature doc promises and is noted here, not counted. The user route
  validates `[A-Z][A-Z0-9_]{0,63}` and refuses the reserved names
  (`http/secrets.go:36-41`, closes L-5 on the api side); `GET /secrets`
  reads `secrets.Meta`, which has no value field; the `secret_put` log
  line and both audit rows carry the project id and the name, never the
  value. `DEKCache` is 10 minutes in memory. No finding.
- **07 cli** (reviewed 2026-09-20 by the M3 integration session): the
  sync is an allowlist of exactly the four rows of `guest-conventions.md`
  (`creds.go` `credRows` plus the two git identity keys), sent as a
  single-file tar over the user's own SSH session with the mode in the
  header and a `chmod` after, so nothing outside the list can travel and
  the api never sees them; `.claude/.credentials.json`,
  `.gemini/oauth_creds.json` and SSH keys are pinned absent by
  `run_integration_test.go`. The CLI's own refresh token is
  `~/.config/repose/credentials.json` 0600 (keychain on macOS). One
  finding, L-12: the mtime rule of `secrets.md` is not implemented.
